# Установка, перенос и обслуживание

## 1. Перед началом

Работайте с копией комплекта. Сохраните исходный SQL отдельно. Запишите данные своего размещения:

| Настройка | Значение вашей установки |
| --- | --- |
| Домен сайта | __________________ |
| Панель хостинга | __________________ |
| Папка сайта на сервере | __________________ |
| Адрес и порт базы | __________________ |
| Имя базы | __________________ |
| Пользователь базы | __________________ |
| Email ответственного администратора | __________________ |
| Где хранятся резервные копии | __________________ |

Пароли храните отдельно в менеджере паролей, а не в этой инструкции. На хостинге выбирайте тариф с PHP, MySQL/MariaDB, HTTPS, резервными копиями и задачами по расписанию. Желательно наличие SSH или WP-CLI для безопасного переноса адреса. Официальные требования: [wordpress.org/about/requirements](https://wordpress.org/about/requirements/).

## 2. Локальная установка

Короткая инструкция находится в README. На Windows запустите MySQL/MariaDB, затем из папки комплекта выполните `./tools/setup.ps1`. Установщик предложит параметры подключения и новый доступ администратора. После импорта запустите `./tools/start.ps1`.

Этот комплект не устанавливает сервер базы данных. Для просмотра можно использовать Local: запустите его сайт для работы базы и возьмите адрес, порт и пользователя на вкладке Database. PHP установщик найдёт автоматически. Если сервер уже настроен самостоятельно, передайте путь к PHP параметром `-PhpBinary`.

## 3. Установка на хостинг с доступом к командной строке

1. В панели хостинга создайте сайт и **пустую отдельную базу**. Создайте пользователя базы с доступом к ней. На действующей базе установка запрещена.
2. Загрузите комплект в закрытую папку сервера. Настройте корневой каталог сайта на её `public/`. Если хостинг не позволяет выбирать корень, разместите содержимое `public/` в выданной папке сайта, а `database/` и `tools/` рядом с ней вне открытого доступа, сохранив для установщика структуру комплекта на время установки.
3. Задайте в окружении `WEB_AVTOBUS_DB_PASSWORD` и `WEB_AVTOBUS_ADMIN_PASSWORD`. Новый пароль администратора — минимум 12 символов. Не записывайте пароль в публичный файл или аргумент команды. Способ ввода переменных зависит от оболочки хостинга; при необходимости попросите его поддержку.
4. Выполните команду, подставив реальные **несекретные** параметры:

```text
php tools/install.php --db-host=DB_HOST:3306 --db-name=NEW_DATABASE --db-user=DB_USER --url=https://example.org --admin-user=admin --admin-email=admin@example.org --environment=production
```

Базу заранее создаёт хостинг. Флаг `--create-database` нужен только там, где пользователю базы разрешено создавать базы. Установщик создаёт личный `public/wp-config-local.php`, новый пароль, новые ключи и заменяет локальные ссылки. Он проверяет количество импортированных записей. После выполнения удалите временные переменные окружения.

5. Проверьте сайт и войдите новым доступом. В настройках постоянных ссылок нажмите «Сохранить» без изменения структуры.

## 4. Установка без SSH

1. Загрузите содержимое `public/` в папку сайта. Остальные папки не публикуйте.
2. Создайте пустую базу и импортируйте `database/database.sql` через phpMyAdmin панели хостинга. При ограничении размера импорта обратитесь в поддержку, не разбивайте SQL на случайные куски.
3. Скопируйте `wp-config-local.example.php` в `wp-config-local.php`. Заполните имя базы, пользователя, пароль и адрес из панели хостинга. Префикс оставьте `wp_`, окружение — `production`.
4. Замените все восемь значений ключей новыми случайными ключами. Их можно получить в официальном сервисе [WordPress](https://api.wordpress.org/secret-key/1.1/salt/); переносите только значения к соответствующим названиям массива, а не строки `define(...)` целиком. Без замены примера сайт намеренно не запускается.
5. Попросите специалиста или поддержку хостинга выполнить безопасную замену `http://127.0.0.1:8083` на конечный адрес во всех таблицах. В WP-CLI это `wp search-replace 'http://127.0.0.1:8083' 'https://example.org' --all-tables-with-prefix --skip-columns=guid` из корня WordPress. Нельзя делать обычную текстовую замену в SQL: часть настроек содержит длины строк.
6. Импортированная учётная запись `admin` заблокирована до назначения нового пароля. Через phpMyAdmin задайте ей ваш действующий `user_email` в `wp_users`; в `wp_options` задайте действующий `admin_email`. Настройте отправку почты на хостинге, затем откройте `/wp-login.php` и запросите новый пароль. Если почта не работает, специалист может установить пароль штатной командой `wp user update admin --prompt=user_pass` и задать email через WP-CLI. Прежний пароль сайта не используется.
7. Откройте админку, проверьте адреса WordPress и сайта в общих настройках и сохраните постоянные ссылки. Убедитесь, что активны тема `autobus03` и плагин `autobus03-content`.

При ручной установке новая роль по умолчанию задаётся администратором в общих настройках; самостоятельную регистрацию оставьте выключенной. Четыре согласованные роли уже сохранены в импортированной базе; плагин обеспечивает их права.

## 5. Домен и HTTPS

1. Добавьте домен в панель хостинга и укажите правильную папку сайта.
2. В панели регистратора домена укажите DNS-серверы хостинга **либо** измените A-запись на предоставленный IPv4. AAAA добавляйте только при наличии работающего IPv6 хостинга. Для `www` используйте запись, которую рекомендует провайдер. Существующие MX и записи почты не удаляйте.
3. Дождитесь обновления DNS. Проверяйте и основной домен, и `www`; скорость зависит от прежнего срока кэширования записей. IP не угадывайте — возьмите его у хостинга.
4. После привязки выпустите бесплатный сертификат Let's Encrypt или сертификат через панель хостинга. Включите автоматическое продление и включите в сертификат используемые варианты домена.
5. Проверьте открытие HTTPS без предупреждений. После этого задайте адрес сайта с `https://` и безопасно замените старые ссылки, если первоначальная установка была по HTTP.
6. Включите перенаправление HTTP → HTTPS в панели хостинга. Если используется прокси/CDN, настройки перенаправления согласуйте с поддержкой, чтобы не получить бесконечный цикл.

Названия кнопок у хостингов отличаются. Наличие сертификата не проверяется локальной копией; отдельно проверьте продление на сервере. Способ установки сертификата описан у [Let's Encrypt](https://letsencrypt.org/getting-started/).

## 6. Постоянные ссылки и планировщики

Apache должен разрешать правила WordPress из `.htaccess`. На Nginx поддержка хостинга настраивает передачу несуществующих файлов в `index.php`, например `try_files $uri $uri/ /index.php?$args;`. Конкретная серверная конфигурация зависит от панели. При ошибке 404 у внутренних страниц сначала пересохраните «Настройки → Постоянные ссылки».

Выберите «Настройки → Общие → Часовой пояс → Иркутск», то есть `Asia/Irkutsk`. Это время Улан-Удэ, UTC+8; дополнительный московский часовой пояс не используется.

Для публикации новостей и применения графиков независимо от посетителей добавьте серверную задачу **каждую минуту**. Возможные способы — WP-CLI `wp cron event run --due-now --path=/ABSOLUTE/PATH/TO/public` либо запуск PHP `/ABSOLUTE/PATH/TO/public/wp-cron.php`. Пути и команду PHP уточните у хостинга. Не запускайте оба способа одновременно. После проверки серверного запуска добавьте `define('DISABLE_WP_CRON', true);` в `wp-config.php` перед подключением `wp-settings.php`, чтобы отключить запуск от посещений. Локальный простой PHP-сервер отключает фоновый запуск сам; полноценный локальный Nginx работает штатно.

Проверьте задачу временным черновиком, запланированным на ближайшие минуты. Не проверяйте планировщик изменением реального графика без согласования. На выключенном сервере или компьютере задачи не выполняются. Без серверной задачи стандартный WordPress может выполнить просроченную публикацию при следующем посещении сайта.

## 7. Проверка после установки

Откройте главную, услуги, расписание, несколько маршрутов во всех направлениях и днях, новости и отдельную новость, предприятие, вакансии, контакты, соглашение и cookie. Проверьте изображения, ссылки меню, поиск, мобильное меню, кнопки дней расписания, печать и версию для слабовидящих. Принятие и отклонение cookie должны сохранять выбранный вариант.

Войдите в админку. Сохраните пробный черновик новости и проверьте предпросмотр, затем удалите пробу. Создайте отдельные учётные записи сотрудников и проверьте их доступ по ROLES.md. Проверьте восстановление пароля и отправку служебной почты на вашем хостинге.

Для дополнительной проверки файлов и ссылок из корня комплекта выполните `php tools/check.php`. Отчёт не заменяет проверку DNS, HTTPS, почты и внешних сервисов.

## 8. Обновления и резервные копии

Перед обновлением сохраните SQL и файлы, особенно `wp-content` и личную конфигурацию. В панели хостинга включите регулярные копии и проверьте, что их можно скачать и восстановить. Для активно редактируемого сайта удобна ежедневная копия базы; срок хранения согласуйте с организацией. Периодически проверяйте восстановление в отдельной базе.

Обновляйте WordPress сначала на тестовой копии. После обновления проверьте расписания, планировщики и админку. Собственные тему и плагин нельзя заменять случайным одноимённым продуктом. Не выдавайте права администратора для повседневного добавления новостей, используйте отдельные рабочие записи и длинные уникальные пароли.

При восстановлении сначала остановите редактирование. Верните файлы и базу **одной даты**, проверьте адрес сайта и настройки подключения. Откройте ожидающие задания и отмените неактуальные: восстановленная база может содержать уже прошедшие даты публикации.

## 9. Если возникла проблема

| Симптом | Что проверить |
| --- | --- |
| «Сайт ещё не настроен» | Наличие и имя `wp-config-local.php`, читаемость файла, заполнение образца. |
| Ошибка подключения к базе | Включён ли MySQL; адрес и порт; имя базы; пользователь и его права; пароль. |
| Ошибка импорта или непустая база | Создайте новую пустую базу. Не повторяйте импорт поверх части таблиц. |
| Внутренние страницы дают 404 | Постоянные ссылки, `.htaccess` или правила Nginx. |
| Перенаправляет на локальный адрес | Замена адреса в базе не выполнена или выполнена неполностью. |
| Нет изображений | Загружена ли вся `uploads/`, правильный адрес в базе, права чтения файлов. |
| HTTPS выдаёт предупреждение | DNS, срок сертификата, имя домена в сертификате, HTTPS-ссылки ресурсов. |
| Не получается войти | Новый доступ после установки, правильный домен, роль пользователя; сброс пароля и работа почты. Старый пароль в комплект не входит. |
| Задание не исполнилось вовремя | Часовой пояс, серверная задача каждую минуту, статус задания, права его автора. |
| Сотрудник не видит раздел | Назначенная роль и активность `autobus03-content`; не выдавайте администратора вместо нужной роли без причины. |
| Белая страница или ошибка 500 | Журнал PHP у хостинга, версия PHP, активные тема и плагин. Диагностируйте на копии; не показывайте посетителям текст ошибки. |

При обращении к специалисту сообщите адрес страницы, время ошибки, действие и снимок экрана. Пароли и секретные ключи на снимок не включайте.
