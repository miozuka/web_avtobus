# Как устроен проект

## Разделение файлов

`public/` — обычная установка WordPress. Папки `wp-admin/` и `wp-includes/` оставлены в штатной структуре. Менять ядро ради оформления или поведения сайта не нужно.

В `wp-content/themes/autobus03/` находятся шаблоны, CSS, изображения оформления, шрифты и JavaScript. В `wp-content/plugins/autobus03-content/` — данные разделов, формы управления, права сотрудников и планировщики. При смене темы записи остаются в базе, но их привычное оформление требует темы autobus03. Сайт не зависит от внешнего конструктора страниц.

`uploads/` содержит пользовательские файлы и размеры изображений из метаданных WordPress. Варианты размеров нужны для адаптивной загрузки. `languages/` содержит переводы. Одна стандартная тема оставлена для диагностики; она не активна. Папки базы, документации и инструментов находятся рядом с `public/`, а не внутри открытого сайта.

## Тема autobus03

| Файл или папка | Назначение |
| --- | --- |
| `functions.php`, `inc/` | Подключение функций, настроек, ресурсов и помощников отображения. |
| `front-page.php` | Главная страница и порядок её готовых блоков. |
| `home.php`, `single.php` | Список новостей и отдельная новость; видео добавляется в содержимое WordPress. |
| `page-*.php`, `page.php` | Специальные разделы и обычные страницы. |
| `templates/timetable.php` | Страница графика конкретного маршрута. |
| `template-parts/` | Повторяющиеся части страниц, в том числе график и карточка вакансии. |
| `assets/` | Стили, сценарии, шрифты и изображения оформления. |
| `inc/customizer.php` и подключаемые схемы страниц | Разрешённые поля настроек темы. Обычный сотрудник меняет их через админку. |

Программные изменения добавляйте в собственную тему и плагин, а не в ядро WordPress. Публичный текст выводите с экранированием. Для новых редактируемых значений используйте действующие схемы и помощники темы, чтобы поле появилось в редакторе на сайте.

Главный файл подключает модули из `includes/`. Файлы интерфейса находятся в `assets/`.

| Модуль | За что отвечает |

| `route-editor.php` | Номер маршрута, направления и фактическое время отправления; создание страницы графика. |
| `route-planner.php`, `route-planner-admin.php` | Будущие версии графиков, очередь, отмена, защита от конфликтов и применение изменений. |

| `staff-access.php`, `job-access.php`, `staff-manager.php`, `staff-directory.php` | Права, роли, сотрудники и приостановка доступа. |
| `admin-workspace.php`, `editing-navigation.php` | Рабочее место, карта страниц и поиск настройки. |

Формы сохраняют данные через WordPress с проверкой прав и защитного кода. Скрытая кнопка сама по себе не является защитой. Редактор просмотра использует те же формы и обработчики; отдельного способа записать произвольный HTML в обход проверки нет. Гостям не передаются служебные данные редактора.

## Данные маршрутов

Маршрут хранится как `agm_route`, направление с временем — как `agm_departure`, будущая версия — как `agm_route_plan`. Страница графика связана с маршрутом через `_autobus_route_id`; обратная связь хранится в `_autobus_timetable_page_id`. Время каждого направления хранится в отдельных полях `_autobus_weekday`, `_autobus_weekend`, `_autobus_saturday`, `_autobus_sunday`, `_autobus_weekday_saturday`, `_autobus_daily`, `_autobus_unspecified`.

Пустой вариант не отображается. Отдельные варианты дней не должны молча заменять друг друга. При переносе общий выходной график записан отдельно в субботу и воскресенье. Для маршрута 2А по согласованию используется такое же расписание, как у 2. Два прежних направления дачного маршрута 12 сохранены в черновиках, действующая страница показывает актуальные два направления.

Источник переноса хранится в `_autobus_tt_source`. Поле `_autobus_tt_imported` содержит подпись «Обновлено: дата, время · Улан-Удэ». Его обновляет `agm_save_route_schedule()` после сохранения направлений, в том числе при исполнении плана.

Планировщик хранит полный подготовленный вариант, срок, состояние, автора и версию. Каждая версия заменяет предыдущую целиком. При применении проверяются действующие права автора и отсутствие несогласованных изменений. Запись выполняется в транзакции. Отложенные новости используют штатное событие WordPress `publish_future_post`.

Все даты ввода относятся к `Asia/Irkutsk`, то есть Улан-Удэ, UTC+8. В базе момент задания хранится как UTC. Для независимого от посетителей запуска нужен серверный cron каждую минуту.

## Роли

В базе сохранены четыре роли: администратор, маркетолог, диспетчер, отдел кадров. Подробности находятся в [ROLES.md](ROLES.md). Общие информационные карточки используют `agm_items`, вакансии и преимущества работы — `agm_jobs`, маршруты и планы — свои отдельные группы прав.

`job-access.php` один раз переносит прежний доступ к вакансиям и отмечает это через `agm_job_access_version`. Роли организации сохраняются в `wp_user_roles`. Отметки `removed` в `agm_staff_role_overrides` предотвращают восстановление четырёх удалённых базовых ролей. Установщик не заменяет выбранную роль по умолчанию.

## Установка и личная конфигурация

`public/wp-config.php` загружает массив из `wp-config-local.php` либо из файла, указанного переменной `WEB_AVTOBUS_CONFIG`. Второй вариант позволяет проверять чистый комплект, сохраняя доступы вне его папки. Образец находится в `wp-config-local.example.php`; действующих ключей в нём нет.

`tools/install.php` разрешает импорт только в пустую базу, сверяет число строк с manifest.json, создаёт ключи и назначает новый доступ администратора. Замена адреса учитывает сериализованные массивы WordPress; обычная замена текста в SQL для этого не подходит. Поле GUID намеренно не переписывается.

`tools/start.ps1` использует установленный PHP. Если найден локальный Nginx, запускает несколько PHP-обработчиков. Временная конфигурация и журналы создаются в системной временной папке; при штатной остановке серверов папка удаляется. Без Nginx используется простой сервер PHP с ограничениями фоновых запросов. `tools/check.php` проверяет вывод страниц, внутренние ссылки и файлы изображений.

## Что важно сохранять при обслуживании

Сохраняйте базу, всю uploads, собственные тему и плагин и личную конфигурацию одной даты. Ссылки маршрутов и ID записей участвуют в связях — не переносите их вручную по отдельности. Не очищайте ожидающие задания или историю настроек без согласования. Перед обновлением делайте копию и проверяйте изменения отдельно от действующего сайта.
