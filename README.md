# Сайт МУП «Городские маршруты»

Это готовый комплект сайта для установки на другом компьютере или хостинге. В нём находятся WordPress, тема, плагин управления содержимым, изображения и свежая база данных. Рабочий сайт, с которого сделана копия, не изменён.

Для размещения на домене начните с раздела [«Как запустить рабочий сайт в интернете»](#как-запустить-рабочий-сайт-в-интернете). Для проверки на своём компьютере есть [локальная установка](#как-запустить-сайт-на-своём-компьютере). Пароли хостинга и базы передавайте отдельно.

## Что находится в папке

| Папка или файл | Для чего нужен |
| --- | --- |
| `public/` | Сам сайт. Именно эту папку нужно открывать через веб-сервер. |
| `public/wp-admin/`, `public/wp-includes/` | Стандартные файлы WordPress. Вручную их не редактируют. |
| `public/wp-content/themes/autobus03/` | Оформление сайта: страницы, стили, анимации и сценарии. |
| `public/wp-content/plugins/autobus03-content/` | Карточки, расписания, планировщики, роли и удобные формы редактирования. |
| `public/wp-content/uploads/` | Фотографии, документы и другие файлы медиатеки. Сохраняйте папку целиком. |
| `public/wp-content/languages/` | Переводы WordPress. |
| `database/database.sql` | Данные сайта для импорта в отдельную пустую базу. |
| `database/manifest.json` | Сведения об экспорте и число записей для проверки установки. |
| `tools/setup.ps1`, `tools/start.ps1` | Установка и запуск локальной копии на Windows. |
| `tools/install.php`, `tools/check.php` | Установка через PHP и проверка страниц, файлов и ссылок. |
| `docs/` | [Установка и обслуживание](docs/INSTALL.md), [архитектура](docs/ARCHITECTURE.md), [роли сотрудников](docs/ROLES.md). |

Кроме рабочей темы оставлена одна стандартная тема WordPress на случай диагностики. Активен только плагин содержимого сайта. Дополнительные плагины для редактирования устанавливать не требуется.

## Как запустить рабочий сайт в интернете

Чтобы посетители открывали сайт по домену, нужен **хостинг с PHP и базой данных**. GitHub хранит файлы проекта; обычный GitHub Pages не запускает этот WordPress-сайт. Local и команды `setup.ps1` / `start.ps1` предназначены для проверки на компьютере. После переноса на хостинг держать свой компьютер включённым не потребуется.

Ниже `example.org` означает **ваш домен**, а названия базы и пути — примеры. Замените их своими значениями. Если на домене уже работает старый сайт, сначала сохраните его файлы и базу и проверьте новый сайт на тестовом адресе хостинга. Переключайте домен после проверки; при смене тестового адреса на основной потребуется безопасная замена ссылок, описанная ниже.

### 1. Подготовьте хостинг и доступы

В панели хостинга создайте сайт для своего домена. Подойдёт тариф для WordPress со следующими возможностями:

| Что нужно | Что уточнить у хостинга |
| --- | --- |
| PHP | Этот комплект проверен на PHP 8.2.29. WordPress рекомендует PHP 8.3 и новее; перед запуском на другой версии проверьте сайт на ней. Для установщика нужно расширение `mysqli`. |
| База данных | MySQL 8.0 и новее или MariaDB 10.11 и новее — по текущим рекомендациям WordPress. Комплект проверен на MySQL 8.4. |
| Место на диске | Файлы комплекта занимают около 400 МБ; оставьте дополнительное место для новых фотографий, базы и резервных копий. |
| HTTPS | Бесплатный сертификат, например Let's Encrypt, с автоматическим продлением. |
| Работа по расписанию | Возможность запускать задачу каждую минуту: она нужна для новостей и изменений графиков. |
| Перенос и обслуживание | Файловый менеджер или SFTP, импорт базы, резервные копии и отправка служебной почты. Для автоматической установки нужен SSH — доступ к командной строке сервера. |

Текущие рекомендации опубликованы на [сайте WordPress](https://wordpress.org/about/requirements/). Названия разделов панели зависят от провайдера.

Подготовьте домен, доступ в панель хостинга и рабочий email администратора. Пароль от панели хостинга, пароль базы и пароль входа в WordPress — три разных доступа.

### 2. Подключите домен и HTTPS

1. Добавьте домен в панели хостинга. Там же найдите адрес сервера и инструкции по привязке домена.
2. В личном кабинете, где куплен домен, укажите DNS-серверы хостинга **либо** измените A-запись на IPv4, выданный хостингом. Для `www` используйте запись, указанную провайдером. Не удаляйте записи почты. AAAA-запись нужна только при работающем IPv6 на этом хостинге.
3. Дождитесь обновления DNS. Домен должен вести на новый сервер; у разных посетителей записи могут обновиться в разное время.
4. В панели хостинга выпустите SSL-сертификат для домена и используемого `www`, включите автоматическое продление. Проверьте, что `https://example.org` открывается без предупреждения о сертификате. До установки сайта там может быть страница хостинга.
5. Выберите один основной адрес, например `https://example.org`. После проверки HTTPS включите в панели перенаправление с HTTP и дополнительного варианта домена на основной адрес.

Если сертификат не выпускается, сначала проверьте DNS и обратитесь в поддержку хостинга. Порядок получения сертификата через провайдера описан у [Let's Encrypt](https://letsencrypt.org/getting-started/).

### 3. Загрузите файлы в правильную папку

Скачайте проект через **Code → Download ZIP** или клонируйте репозиторий. После распаковки найдите папку, в которой лежат `README.md`, `public`, `database` и `tools`. Имя внешней папки может быть `web_avtobus-main` — это нормально.

У хостинга возможны два варианта размещения:

- **Можно выбрать папку сайта.** Загрузите весь комплект в отдельную папку аккаунта, затем назначьте её `public/` корнем сайта. Корень сайта — папка, файлы которой доступны посетителям. Например, комплект находится в `/home/ACCOUNT/web_avtobus`, а домен открывает `/home/ACCOUNT/web_avtobus/public`.
- **Выдана фиксированная папка, например `public_html`.** В неё должно попасть **содержимое** `public/`: `index.php`, `wp-admin`, `wp-content`, `wp-includes`, конфигурация и остальные файлы, включая скрытый `.htaccess`. Не создавайте лишний уровень `public_html/public/`. Для установки используйте вариант без SSH ниже либо сначала выполните автоматическую установку в закрытой папке комплекта и затем скопируйте содержимое её `public/` в папку домена.

Папки `database/`, `tools/`, `docs/` и каталог `.git/`, если он есть, должны оставаться за пределами корня сайта. Не загружайте SQL в открытый доступ. Диагностический `public/local-xdebuginfo.php` на хостинге не нужен — исключите его из серверной копии.

Если хостинг предлагает «Установить новый WordPress», не запускайте эту установку поверх комплекта: здесь уже есть WordPress, тема, плагин и данные сайта.

### 4. Создайте пустую базу данных

В панели хостинга создайте **новую пустую базу** и пользователя с правами на неё. Запишите имя базы, имя пользователя, адрес сервера базы и порт. Значение `localhost:3306` используйте только если его указал хостинг.

Дальше выберите **один** способ установки. Автоматический установщик сам импортирует SQL; перед его запуском ручной импорт делать не нужно.

### 5. Установите сайт

**Вариант А — есть SSH, автоматическая установка.** Подойдёт системному администратору или поддержке хостинга.

Откройте командную строку сервера и перейдите в закрытую папку комплекта, где находятся `tools/`, `database/` и `public/`. Если конфигурация уже создана для локального просмотра, используйте чистую копию из репозитория и новую пустую базу.

В оболочке Bash введите пароли так, чтобы они не попали в текст команды и историю:

```bash
read -r -s -p 'Пароль базы данных: ' WEB_AVTOBUS_DB_PASSWORD
echo
export WEB_AVTOBUS_DB_PASSWORD
read -r -s -p 'Новый пароль WordPress (от 12 символов): ' WEB_AVTOBUS_ADMIN_PASSWORD
echo
export WEB_AVTOBUS_ADMIN_PASSWORD
```

Выполните установку, заменив параметры своими. В `--url` укажите конечный адрес с HTTPS, без `/wp-admin/` и без `/public/`:

```bash
php tools/install.php \
  --db-host=DB_HOST:3306 \
  --db-name=NEW_DATABASE \
  --db-user=DB_USER \
  --url=https://example.org \
  --admin-user=admin \
  --admin-email=admin@example.org \
  --environment=production
```

Убедитесь, что команда завершилась без ошибок и вывела «Сайт восстановлен». Затем уберите пароли из окружения этого окна:

```bash
unset WEB_AVTOBUS_DB_PASSWORD WEB_AVTOBUS_ADMIN_PASSWORD
```

Установщик импортирует `database/database.sql`, создаёт `public/wp-config-local.php`, назначает новый пароль администратора и заменяет локальный адрес на домен во всех нужных настройках. Дополнительно импортировать базу или менять в ней адрес не требуется. Файл `wp-config-local.php` нужен и на хостинге, несмотря на слово `local` в названии: сохраните его на сервере и не добавляйте в публичный репозиторий.

Если папка домена фиксированная, теперь скопируйте в неё содержимое настроенного `public/`, включая созданный `wp-config-local.php` и `.htaccess`. Проверьте, что настройки попали именно в ту копию, которую открывает домен. Остальные папки комплекта оставьте в закрытом каталоге.

**Вариант Б — SSH нет, установка через панель хостинга.**

1. Загрузите содержимое `public/` в папку домена.
2. Импортируйте `database/database.sql` в пустую базу через phpMyAdmin.
3. В папке домена скопируйте `wp-config-local.example.php` под именем `wp-config-local.php`. Заполните данные базы, оставьте `table_prefix` равным `wp_`, а `environment` — `production`. Замените все восемь примеров ключей новыми случайными значениями. Подробности — в [разделе «Установка без SSH»](docs/INSTALL.md#4-установка-без-ssh).
4. Попросите поддержку выполнить безопасную замену адреса `http://127.0.0.1:8083` на `https://example.org` в базе с сохранением настроек WordPress. Обычная замена текста в SQL может их повредить. Пример команды WP-CLI есть в инструкции. Если импортируете другую, более свежую базу, сначала уточните её исходный адрес.
5. Задайте новый пароль и рабочий email администратора по той же инструкции. Старого рабочего пароля в экспортированной базе нет. Восстановление по email сработает только после настройки адреса пользователя и отправки почты.

Если шаги с базой вызывают затруднения, передайте их поддержке хостинга. Одна загрузка файлов без импорта базы и настройки подключения не запускает сайт.

### 6. Войдите в WordPress и включите планировщики

1. Откройте `https://example.org/wp-admin/`. При автоматической установке логин — значение `--admin-user` (в примере `admin`), пароль — тот, который ввели при установке. При ручной установке используйте заново назначенный доступ.
2. В «Настройки → Общие» проверьте адрес WordPress, адрес сайта и email. Оба адреса должны соответствовать выбранному домену с HTTPS. Для часового пояса выберите **Иркутск (`Asia/Irkutsk`)** — это время Улан-Удэ, UTC+8.
3. В «Настройки → Постоянные ссылки» нажмите «Сохранить изменения» без изменения структуры.
4. Убедитесь, что активны тема `autobus03` и плагин `autobus03-content`. Создайте отдельные записи сотрудников и назначьте [нужные роли](docs/ROLES.md).
5. Попросите хостинг настроить запуск `wp-cron.php` **каждую минуту**, чтобы новости и графики обновлялись даже без посетителей. В панели задач обычно выбирают частоту и команду отдельно. В обычном Linux crontab пример выглядит так:

   ```text
   * * * * * /PATH/TO/php /HOME/ACCOUNT/web_avtobus/public/wp-cron.php
   ```

   Пути заменяет администратор на реальные. При размещении в `public_html` путь к файлу будет другим. После проверки серверной задачи отключите запуск от посещений по [инструкции планировщиков](docs/INSTALL.md#6-постоянные-ссылки-и-планировщики). Не запускайте одновременно несколько одинаковых задач.

### 7. Проверьте сайт перед передачей сотрудникам

- Откройте домен с телефона через мобильный интернет и с компьютера. Это помогает убедиться, что сайт доступен извне.
- Проверьте главную, услуги, расписания, направления и дни, новости, вакансии, контакты, меню и изображения. Ссылки не должны уводить на `127.0.0.1` или старый тестовый адрес.
- Проверьте вход в админку, сохранение пробного черновика и предпросмотр. После проверки удалите пробный материал.
- Запланируйте пробную новость на ближайшие минуты и проверьте её появление; затем удалите пробу. Не меняйте реальный график ради теста.
- Проверьте HTTPS, перенаправление с HTTP, отправку служебной почты и восстановление пароля. Включите регулярные резервные копии базы и файлов.

После этого сотрудники смогут работать через админку по адресу `https://example.org/wp-admin/`. Сайт обслуживает хостинг; команды локального запуска больше не нужны.

**Что написать поддержке хостинга:**

> Нужно развернуть готовый WordPress-проект из https://github.com/miozuka/web_avtobus на домене [указать домен]. Файлы сайта лежат в `public/`, экспорт базы — `database/database.sql`. Нужны отдельная база, замена локального адреса на домен с сохранением настроек WordPress, новые ключи и доступ администратора, HTTPS, отправка почты, резервные копии и задача `wp-cron.php` каждую минуту. Инструкция находится в README и `docs/INSTALL.md`. Папки с базой и инструментами не должны быть доступны посетителям. Существующий сайт необходимо предварительно сохранить.

Пароли передайте поддержке через защищённый канал, предусмотренный хостингом. Не пишите их в README или открытом обсуждении GitHub.

## Как запустить сайт на своём компьютере

Нужны PHP и запущенный MySQL или MariaDB. Эти серверные программы в комплект не входят. На этом компьютере использовались PHP 8.2.29 и MySQL 8.4. Если установлен Local, запустите в нём любой тестовый сайт и возьмите параметры базы на вкладке Database. Для нашего комплекта всё равно нужна **другая, пустая база**: не выбирайте базу действующего сайта.

1. Откройте PowerShell в папке `web_avtobus`.
2. Выполните:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\setup.ps1
   ```

3. Укажите адрес и порт MySQL, имя новой базы, пользователя базы и его пароль. Например, новую базу можно назвать `web_avtobus_test`. Адрес и порт берите из своего сервера, а не из примера.
4. Для адреса сайта укажите `http://127.0.0.1:8088`. Логин администратора по умолчанию — `admin`. Укажите свой email и новый пароль не короче 12 символов. Ввод паролей скрыт.
5. После сообщения об успешном восстановлении запустите:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start.ps1 -Port 8088
   ```

6. Откройте [сайт](http://127.0.0.1:8088/) и [панель управления](http://127.0.0.1:8088/wp-admin/). Войдите данными, которые задали при установке. Для остановки сервера нажмите Ctrl+C в его окне.

Если PHP не найден автоматически, у обоих сценариев есть параметр `-PhpBinary` с полным путём к `php.exe`. Если порт 8088 занят, выберите свободный порт и укажите одинаковый адрес при установке и запуске.

Установщик не перезаписывает заполненную базу. Повторно запускать его для уже установленного сайта не нужно. Для второго независимого просмотра используйте ещё одну копию комплекта и отдельную пустую базу.

## Где менять содержимое

После входа откроется «Управление сайтом». В «Страницы сайта» выберите нужный раздел. Кнопка «Найти настройку» ищет конкретное поле по названию; её можно открыть сочетанием Alt + K.

| Что изменить | Где открыть |
| --- | --- |
| Новости, фотографии и видео внутри новости | «Новости». Для будущей даты — «Планировщик новостей». |
| Номер маршрута, остановки, направления и время | «Маршруты». Для изменений в будущем — «Планировщик». |
| Вакансию, зарплату, требования и условия | «Вакансии». Укажите название и короткое описание; остальные поля заполняйте по необходимости. |
| Заголовки, баннеры, логотип, контакты, соцсети и карты | «Управление сайтом → Тексты и фотографии». |
| Услуги, тарифы, телефоны, документы и другие карточки | Соответствующая задача в «Управлении сайтом». |
| Проездные, льготы и адреса продажи | «Управление сайтом → Проездные и льготы». |
| Порядок и видимость блоков главной | «Управление сайтом → Блоки главной». Скрытие блока не удаляет данные. |
| Меню и ссылки навигации | «Внешний вид → Меню», доступно администратору. |
| Соглашение и другие обычные страницы | «Страницы». Основные разделы сайта ведут в специальные формы. |

На главной автоматически показаны десять последних опубликованных новостей. Для вакансий ограничения по количеству карточек нет. Ненужную сейчас вакансию переведите в черновик: она исчезнет с сайта, но останется в админке.

В расписании доступны будни, суббота, воскресенье и дополнительные варианты дней. Пустой вариант не показывается. Данные общего выходного графика со старого сайта перенесены в субботу и воскресенье. Поле «Выходные» оставлено пустым, но при необходимости его можно заполнить. Дата под графиком обновляется при сохранении расписания.

Оба планировщика используют **Улан-Удэ, UTC+8**. В настройках WordPress это `Asia/Irkutsk`. На хостинге нужен запуск задач каждую минуту; на выключенном компьютере задания не выполняются.

## Редактирование во время просмотра сайта

Войдите в WordPress и откройте сайт. Нажмите «Редактировать сайт → Выбрать элемент», затем нужный текст, фотографию, кнопку, карточку или время отправления. Откроется существующая форма с нужным полем. В панели можно искать задачу и переключаться между текущей страницей и всем сайтом.

После изменения нажмите кнопку сохранения в форме или сверху окна. В редакторе блоков новости используйте штатные кнопки WordPress. При закрытии сохранённой формы страница обновится. Несохранённые правки сопровождаются предупреждением.

Под общей формой настроек есть «Вернуть предыдущие настройки»: сохраняются пять последних состояний раздела. Возврат меняет выбранный раздел целиком. У проездных и льгот есть отдельное восстановление предыдущей версии. Это удобная отмена, но не замена резервной копии.

Сотрудники меняют готовое содержимое без кода. Новую программную функцию или совершенно новый тип оформления добавляет разработчик.

## Сотрудники

Оставлены четыре роли: **Администратор**, **Маркетолог**, **Диспетчер**, **Отдел кадров**. Маркетолог управляет новостями; диспетчер — маршрутами и графиками; отдел кадров — вакансиями. Общие настройки, страницы, меню и доступ сотрудников остаются у администратора.

Для каждого человека создайте отдельную запись через «Сотрудники → Добавить сотрудника». Администратор может создавать, переименовывать и удалять роли, а также выбирать их права. Изменение роли действует для всех сотрудников с этой ролью. Подробности — в [ROLES.md](docs/ROLES.md).

## Настройки подключения и перенос на хостинг

Личные настройки находятся в `public/wp-config-local.php`. Установщик создаёт файл сам. Для ручной настройки есть `public/wp-config-local.example.php`. Указываются база данных, пользователь, пароль и новые ключи WordPress. Действующих доступов в исходном комплекте нет; импортированная учётная запись заблокирована до назначения нового пароля.

Домен задаётся в панели хостинга и параметром `--url` при установке. Его недостаточно вписать в конфигурацию: адрес также хранится в базе. Установщик заменяет его с учётом настроек WordPress. Полный порядок, включая вариант без командной строки, DNS, HTTPS и задачи по расписанию, описан в [INSTALL.md](docs/INSTALL.md).

На сервер публикуется только `public/`. База, инструменты и инструкции должны оставаться вне открытого доступа. Если вы уже установили комплект для проверки, не передавайте созданный `wp-config-local.php` с личными паролями: сохраните его у себя, а организации передайте чистую копию и образец настройки. После новых изменений содержимого или ролей обновите экспорт базы.

## Что сохранено и что исключено

Сохранены все настоящие материалы, настройки, четыре согласованные роли, история правок и файлы медиатеки. Размеры одного изображения, созданные WordPress, тоже нужны: сайт выбирает подходящий вариант для разных экранов. Не удаляйте их как дубликаты.

Не включены пустые автоматические черновики, корзина и связанные с ней записи, временные данные, блокировки редактирования, действующие пароли, сеансы входа и ключи доступа. Файлы кэша, журналы, старые копии, архивы, тестовые сценарии и зависимости разработки в комплект не входят. Резервная копия исходной версии хранится отдельно от этой папки.

## Проверка и ограничения

Комплект проверен 16 октября 2026 года. Установщик восстановил базу в отдельную пустую базу и создал новый доступ администратора. После замены адреса с исходной версией совпали 1153 записи, 5314 полей и настройки содержимого. Все 2168 файлов медиатеки найдены.

Проверены 237 страниц и новостей, 435 используемых изображений и 181 ссылка: ошибок не найдено. В Chrome проверены 11 основных страниц на ширинах 320, 390, 768 и 1440 пикселей — всего 44 вариантов. Проверены мобильное меню, выбор дней и направлений, страницы новостей, сохранение выбора cookie, вход администратора, сохранение черновика, поиск настроек и выбор поля в редакторе на сайте. Ошибок JavaScript в этих сценариях не обнаружено.

Для маркетолога, диспетчера и отдела кадров проверены создание, изменение, публикация и удаление временных материалов через API, открытие разрешённых разделов и отказ в доступе к чужим разделам и сотрудникам. Проверены очереди планировщиков, перенос даты, отмена, запрет раннего запуска, сохранность материалов, применение графика и публикация новости через штатные обработчики WordPress. Время соответствует Улан-Удэ. Проверены синтаксис 93 собственных PHP-файлов, 18 JavaScript-файлов и всех PowerShell-сценариев запуска. Временные материалы и сотрудники после проверки удалены.

Действующие пароли, сеансы входа и ключи исходной установки в комплекте отсутствуют. Созданная для проверки личная конфигурация хранится вне этой папки. Файлы ядра WordPress совпадают с исходными; изменения оформления и поведения сайта при сборке не вносились.

После размещения отдельно проверьте DNS, сертификат и его продление, отправку почты и восстановление пароля, запуск задач каждую минуту, карты, соцсети и внешний сервис обращений. Эти проверки зависят от хостинга и сторонних сервисов. Реальные обращения во внешние системы при подготовке не отправляются. Аналитика подключается только после заполнения идентификаторов и согласия посетителя. Проверка на физических телефонах, в Safari и Firefox не проводилась.
